# Сценарий валидации пользователей внешним сервисом

Этот документ описывает типовой порядок действий, необходимый другому сервису для проверки подлинности и актуальности пользователей с помощью Auth Service.

## Цель
Ниже приведён пример интеграции, при которой сторонний сервис получает JWT от клиента и проверяет его самостоятельно, запрашивая дополнительные данные при необходимости.

## Шаги интеграции
1. **Получить JWKS.** При инициализации сервис выполняет `GET /.well-known/jwks.json` и сохраняет полученный ключ RSA. Ключ обновляется при старте и далее периодически.
2. **Проверить подпись.** При каждом запросе клиента сервис извлекает access токен из заголовка `Authorization`. Подпись JWT проверяется с использованием ключа из первого шага и алгоритма RS256.
3. **Проверить время действия.** Если токен истёк, возвращается ошибка `401` или запрашивается новый access токен через свой фронтенд.
4. **Проверить версию прав.** Из полезной нагрузки токена берётся поле `pv` и сравнивается с сохранённой версией пользователя. При несовпадении стоит запросить данные пользователя заново.
5. **Получить данные пользователя.** При необходимости сервис может обратиться к эндпоинту `GET /api/v1/login/user`, передавая токен в заголовке, чтобы получить email, логин и полный набор разрешений.
6. **Использовать разрешения.** Сервис сравнивает полученные права с требуемыми и принимает решение о допуске к операции.

## Пример валидации токена на Python
```python
from jose import jwt
import requests

JWKS_URL = "https://auth.example.com/api/v1/.well-known/jwks.json"
TOKEN = "<access token>"

jwks = requests.get(JWKS_URL, timeout=5).json()
key = jwks["keys"][0]

payload = jwt.decode(
    TOKEN,
    key,
    algorithms=["RS256"],
    audience=None,
    options={"verify_aud": False},
)
print(payload)
```
Этот пример показывает базовую проверку подписи. Дополнительные проверки (`exp`, `pv`) выполняются самостоятельно.
